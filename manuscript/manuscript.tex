\begin{abstract}
Frontier artificial intelligence models promise to accelerate scientific discovery by automating hypothesis formulation, experimental design, and computational code execution across complex biological domains. Yet contemporary agent platforms operate as disembodied reasoning engines in isolated local environments, generating unversioned scripts, overwhelming consumer hardware on large datasets, and confining scientific discovery to proprietary corporate enclosures. We eliminate this computational bottleneck. Here we introduce an open agentic architecture that provides artificial intelligence with a distributed computational body, transforming public Galaxy cyberinfrastructure into an execution surface governed by immutable directed acyclic graph provenance. To direct long-horizon investigations, we develop Orbit, a scientific research workbench that binds human intent, execution decisions, and remote cloud invocations into a version-controlled research notebook. Complementing this workbench, the Workflow Foundry compiles scientific literature into schema-validated workflows, while unprivileged User-Defined Tools allow agents to execute containerized commands across public supercomputing clusters without administrative intervention. By establishing provenance by construction, this infrastructure prevents the hallucination of scientific method, resolving silent gene identifier traps and converting external workflows into reproducible community assets. All software and universal plugins are freely available, ensuring verifiable scientific discovery across the open public commons.
\end{abstract}

\section{Introduction}

Agentic artificial intelligence is poised to become the predominant paradigm for data analysis across the life sciences \cite{biocoder2024}. A number of successful projects underscore this trajectory. The AI Scientist showed that language models can autonomously generate hypotheses, author code, and run machine learning experiments in local environments \cite{aiscientist2024}. In biomedicine, Google DeepMind's Co-Scientist coordinates multi-agent debate to formulate therapeutic targets \cite{coscientist2026}, while The Virtual Lab organizes specialized agent personas to design experimentally validated nanobodies \cite{virtuallab2025}. In chemistry, Coscientist \cite{boiko2023} and ChemCrow \cite{chemcrow2024} steer robotic synthesis hardware and external modeling tools, while Kosmos extracts knowledge across multi-hour research sessions \cite{kosmos2025}. 

Translating reasoning into empirical discovery is a balancing act between ever-improving frontier models and domain-specific procedural skills. Without structured guidelines, models guess command-line parameters, corrupt file headers, and hallucinate analytical steps. Specialized biomedical frameworks address this gap. Platforms such as Biomni \cite{huang2025biomni} and ToolUniverse \cite{gao2025democratizingaiscientistsusing} equip agents with hundreds of curated tools, database connectors, and execution rules spanning sequence alignment, differential expression, and variant calling. Modern agent runtimes organize these capabilities into modular skills---declarative packages that enforce strict parameter constraints and output schemas. Yet procedural skills solve only half the problem. A skill can formulate a syntactically valid command, but that command must still execute on physical compute infrastructure.

Today, autonomous agents run primarily on the researcher's local workstation. Personal machines can be sufficient for many tasks, but they fail on genome assembly, high-throughput read alignment, or analyses requiring high-end GPUs. In principle, agents can orchestrate external compute. Given administrative credentials, an agent can launch Slurm clusters, provision Kubernetes pods, or spin up cloud virtual machines. In practice, researchers rarely possess that level of administrative control. Institutional high-performance computing administrators will not grant autonomous agents unrestricted cluster access due to security risks, shared filesystem vulnerabilities, and resource contention. Commercial cloud integrations offer an alternative, but they impose steep subscription costs and private billing. Unless a laboratory owns a dedicated private cluster, connecting autonomous agents directly to institutional compute resources remains impossible today.

Public scientific cyberinfrastructure eliminates this deadlock. For two decades, the Galaxy platform has maintained an open, community-governed computational ecosystem for executing heterogeneous scientific tools at scale \cite{galaxy2024}. Galaxy schedules computational jobs across distributed supercomputing clusters without administrative friction. This creates an open agentic execution surface that already operates worldwide. Through established public servers, agents gain immediate access to national research allocations, including the ACCESS ecosystem in the United States, the European Open Science Cloud and de.NBI in Europe, and Pawsey and NCI in Australia. Galaxy couples this distributed compute to thousands of containerized bioinformatics tools and petabyte-scale reference genomes, providing an operational execution fabric that requires zero local configuration.

This infrastructure also eliminates the computational disorder frequently left behind by autonomous tools. During multi-day investigations, agents routinely generate dozens of ad hoc scripts, manipulate data through undocumented commands, and scatter intermediate files across temporary directories. Tracking computational state across these protracted sessions quickly becomes intractable. Galaxy replaces this local sprawl with permanent cloud artifacts hosted on public UseGalaxy instances. When an agent operates through Galaxy, every input dataset, tool invocation, exact parameter setting, and intermediate result lives in a persistent, shareable history. These objects form an immutable directed acyclic graph that any investigator can inspect, reproduce, verify, and share.

Here we present an open agentic architecture that bridges autonomous reasoning directly to distributed public computing infrastructure. The framework unites four computational components. First, we introduce Orbit, an open-source scientific research workbench that records hypotheses, analytical plans, execution logs, and cloud invocations directly into a living, version-controlled research notebook. Second, we develop the Workflow Foundry, a casting compiler that translates external scientific literature, Nextflow \cite{nextflow2017} and CWL \cite{cwl2022} pipelines, and free-form research queries into schema-validated Galaxy workflows, eliminating language model hallucination through deterministic graph validation. Third, we establish User-Defined Tools, unprivileged containerized definitions that allow agents to register and run custom tools on remote Galaxy compute clusters safely using sandboxed ECMAScript templating. Fourth, we provide production plugins across major agent platforms---including Claude Code, Google Antigravity, and OpenAI Codex---allowing investigators to connect frontier models to public cyberinfrastructure. By grounding autonomous agents in public infrastructure, we replace isolated computational silos with verifiable, reproducible scientific discovery.

\section{Results}

\subsection{The Flow}

In our architecture, an investigator drives scientific analysis through an autonomous agent. The framework is agent agnostic. Researchers can operate from any general-purpose agent runtime, including Claude Code, OpenAI Codex, Google Antigravity, Open Code, or Pi.dev \cite{agenticplugins2026}. To support life scientists directly, we also developed Orbit, a specialized research workbench described in detail below \cite{orbit2026}. Orbit incorporates domain capabilities that simplify remote execution, enforce structured record-keeping, and streamline the agentic utilization of Galaxy cyberinfrastructure.

The overall operational flow requires only two prerequisites (Figure~\ref{fig:architecture}). First, the investigator needs a Galaxy account. Registration is free and provides a personal API key, allowing the agent to drive Galaxy services programmatically without administrative friction. Second, the user needs access to a large language model. This can be a commercial frontier model, an open-weight model from independent providers, or a local model hosted on the user's workstation. The agent bridges to the Galaxy platform through two complementary mechanisms: modular skills and a Model Context Protocol (MCP) server \cite{galaxymcp2026, galaxyskills2026}. Skills supply procedural domain intelligence, teaching the model standard conventions for biomedical data analysis. The Galaxy MCP server equips the agent with structured programmatic endpoints, instructing it how to query datasets, execute tools, and monitor computational state.

An investigation begins interactively. The user provides a natural language prompt defining a scientific objective. The agent then formulates an initial analytical plan. The plan lays out a sequence of tool executions designed to transform raw biological inputs into final results. Tools in this execution chain fall into two categories:
\begin{itemize}
    \item \textbf{Pre-existing Galaxy tools:} Galaxy maintains thousands of community-curated, peer-reviewed bioinformatics tools spanning genomics, transcriptomics, proteomics, and structural biology \cite{galaxy2024}.
    \item \textbf{Novel or missing tools:} Specialized operations occasionally require software not yet present in the Galaxy catalog, which the agent either authors dynamically as custom wrappers or imports from external container registries.
\end{itemize}
Before any heavy computation begins, the investigator reviews and approves the drafted plan. This conversational checkpoint enables researchers to discuss unfamiliar analytical steps with the agent, explore alternatives, and align tool parameters with biological intent.

Once the plan is approved, the agent dry-runs the analytical pipeline. It extracts a small subset of data to test the end-to-end execution path rapidly. Whenever possible, this initial validation executes directly on the user's local machine. Local execution allows rapid debugging without consuming shared cloud allocations. However, local prototyping is skipped under two conditions. First, tasks involving heavy tools---such as deep learning models requiring large neural network weights---cannot be installed or executed on standard workstations. Second, restricted operating environments, such as Windows systems lacking native POSIX environments or container virtualization, prevent local execution. In these situations, the agent bypasses local prototyping and conducts verification directly on remote cyberinfrastructure.

With the workflow verified, the agent transitions to remote execution on Galaxy:
\begin{itemize}
    \item \textbf{Data upload:} The agent uploads input datasets, reference annotations, and metadata collections into the user's Galaxy account.
    \item \textbf{Tool invocation and extension:} It invokes pre-installed Galaxy tools or provisions novel utilities dynamically using User-Defined Tools (UDTs) \cite{galaxyudt2026}.
    \item \textbf{Workflow assembly and validation:} The agent links computational stages into a formal Galaxy workflow definition. It binds inputs and outputs across collection structures, validates directed graph topology, and verifies schema conformance before execution.
    \item \textbf{Step-by-step execution:} It executes the analytical plan sequentially, passing intermediate dataset collections between stages.
    \item \textbf{Self-healing execution:} When an individual step encounters a failure, the agent inspects standard error logs, identifies parameter misconfigurations or format mismatches, modifies the execution command, and reruns the step until it completes cleanly.
    \item \textbf{Result generation:} It synthesizes final outputs, including quality metrics, statistical tables, and publication-ready visualizations.
\end{itemize}

As mentioned earlier, this entire process can be driven from any agent and works well from command-line environments such as Claude Code. Yet the terminal paradigm may still be unfamiliar to bench biomedical researchers. To ease this transition, we built Orbit \cite{orbit2026}. Orbit is a dedicated desktop application that simplifies researcher interaction with autonomous agents. It functions across model tiers, driving commercial frontier models, open-weight alternatives, and locally hosted models via Ollama. Unlike generic programming assistants, Orbit embeds deep Galaxy domain intelligence and enforces disciplined scientific usage patterns. Central to this discipline is the living research notebook. As an investigation unfolds, the notebook records a continuous narrative of the analysis: initial hypotheses, tool parameters, execution rationale, and analytical artifacts such as figures, charts, and summary tables. At the conclusion of an investigation, Orbit deposits this notebook directly into the user's Galaxy history. While external agent runtimes can perform this deposit through MCP calls, Orbit maintains the notebook as an always-visible, primary canvas. The notebook becomes the permanent living memory of the investigation. It preserves complete computational provenance. Independent investigators can inspect and share this record, while subsequent agents can ingest it to validate, reproduce, or extend previous findings.

\subsection{Galaxy for supercharging agents}
Galaxy is an integrated analysis environment that pairs a web-based interface with distributed public computing infrastructure \cite{galaxy2024}. In the United States, Galaxy provides direct access to national research cyberinfrastructure coordinated through the ACCESS program (Advanced Cyberinfrastructure Coordination Ecosystem: Services \& Support). Through this unified interface, tools run transparently across national supercomputing centers, including the Texas Advanced Computing Center (Stampede3, Vista, and Corral), the Pittsburgh Supercomputing Center (Bridges-2), the San Diego Supercomputer Center (Expanse), Purdue University (Anvil), and Indiana University (Jetstream2). Centralized dataset storage at Penn State manages petabytes of user data, while reference databases synchronize globally across the CVMFS network.

Galaxy does not treat compute nodes as interchangeable commodity servers. For every tool in its catalog, the platform determines how to schedule appropriate computational resources. Galaxy achieves this through Total Perspective Vortex, a dynamic resource router, and Pulsar, a remote job execution engine that dispatches tasks without requiring a shared filesystem. Resource routing adapts to the physical requirements of the assay:
\begin{itemize}
    \item \textbf{High-throughput parallel tasks:} Embarrassingly parallel jobs, such as raw sequence quality control and read mapping, route to multi-core compute nodes configured with 32 to 128 processor cores.
    \item \textbf{Memory-intensive computations:} Tasks requiring massive memory, including de novo genome assembly and large k-mer indexing, route to specialized high-memory nodes equipped with terabytes of RAM.
    \item \textbf{Accelerated models:} Deep-learning workflows, structural predictors, and language models route to dedicated GPU clusters powered by NVIDIA hardware accelerators.
\end{itemize}
When scheduling each job, Galaxy evaluates dataset dimensions and historical execution metrics \cite{tyryshkina2019}. By analyzing past walltimes and memory footprints, the platform dynamically predicts resource consumption and adjusts queue reservations accordingly.

Autonomous agents cannot use this national cyberinfrastructure on their own. Institutional high-performance computing centers cannot grant autonomous agents unrestricted SSH credentials, interactive shell access, or raw batch scheduler privileges. Unsupervised agents risk saturating shared filesystems, exhausting project allocations, and triggering security hazards. Galaxy resolves this impasse by acting as a middle layer between autonomous reasoning and high-performance computing. Rather than managing Slurm scripts, staging files across remote clusters, or troubleshooting local environment modules, the agent interacts with Galaxy through a structured REST API and the Model Context Protocol \cite{galaxymcp2026}. Galaxy validates each request, verifies tool parameters, isolates dependencies within container images, and routes the execution across national clusters. The agent receives a clean, predictable execution interface.

This architecture scales because Galaxy is engineered for high-throughput production. The platform is not a prototype built for demonstration. Worldwide, Galaxy supports over 650,000 registered researchers. Public instances process hundreds of thousands of jobs every month, with the UseGalaxy national infrastructure alone executing approximately 2,000,000 analysis jobs monthly. Galaxy has operated continuously at this scale for two decades. Because the platform natively handles concurrent execution, queue failover, and massive multi-tenant data movement, it easily absorbs the intensive demands of autonomous AI agents. Yet real-world biological workflows often require custom software utilities absent from pre-installed tool catalogs. For these bespoke analytical steps, the architecture relies on User-Defined Tools.

\subsection{Extensibility via User-Defined Tools}

All global Galaxy instances contain thousands of curated tools. Historically, however, tool installation required administrative privileges. While central curation guarantees software quality and reproducibility, it creates friction when an analysis requires bespoke data-formatting scripts or novel utilities absent from official catalogs. User-Defined Tools (UDTs) provide dynamic extensibility on public infrastructure \cite{galaxyudt2026}. Introduced in Galaxy 26.1, UDTs allow unprivileged users and autonomous agents to register and run custom tools dynamically. A UDT is declared as a compact YAML specification that pairs an immutable container image with typed inputs and an isolated command template. Because templates evaluate using sandboxed ECMAScript rather than arbitrary host scripts, custom tools execute safely on shared supercomputing clusters.

UDTs span a broad spectrum of computational complexity. At one end, an agent can author a lightweight UDT in seconds to convert unusual tabular formats, filter metadata, or glue disparate workflow steps together. At the opposite end, UDTs orchestrate heavy foundation models requiring dedicated GPU acceleration. Later in this manuscript, we demonstrate this capability in our \textit{Plasmodium vivax} case study. There, the agent authors custom UDTs that route 4.4-gigabyte protein language models directly to NVIDIA A100 GPUs on national supercomputers, executing complex structural alignments without manual system administration.

\subsection{Living Research Notebooks and Shared Provenance}

Every completed analysis yields three complementary artifacts: an executable Galaxy workflow, a structured Galaxy history, and a living research notebook. The Galaxy workflow encapsulates the parameterized directed acyclic graph. It decouples the analytical protocol from specific sample instances. This separation enables immediate re-execution across new cohorts or high-throughput batch scaling. While the Galaxy history preserves physical data lineage and intermediate outputs, the research notebook captures the epistemic narrative. Structured similarly to an \texttt{AGENTS.md} record, the notebook documents the complete scientific context: initial hypotheses, biological motivations, human review checkpoints, and quantitative interpretations.

This triad establishes complete computational provenance. Rather than receiving an isolated PDF report with static figures, independent researchers receive the entire experimental fabric. Galaxy workflows, execution histories, living notebooks, and containerized tool definitions can be published, cited, and shared via persistent identifiers. Collaborators can inspect every intermediate dataset, examine why specific parameters were chosen, or re-execute the complete pipeline on public computing resources with a single click. By coupling autonomous agents to open infrastructure, biological discovery becomes fully transparent, verifiable, and reproducible.

\subsection{Compiling Scientific Procedures with Workflow Foundry}

When large language models attempt to author complex scientific pipelines directly from unstructured prompts, they encounter recurring failure modes. Models hallucinate nonexistent tool identifiers, drop version revision suffixes, fabricate unsupported parameter flags, and generate syntax that workflow parsers reject immediately. Conventional prompt engineering and hand-authored instructions degrade quickly as software ecosystems evolve.

We address this limitation through Workflow Foundry, a specialized compiler that translates computational procedures into validated agent skills \cite{foundry2026}. Rather than treating workflow construction as an unconstrained generative task, the Foundry decomposes scientific translation into modular, schema-enforced units called Molds. Each Mold specifies an atomic transformation step. Typical Molds extract input parameter schemas from published prose, map Nextflow process channels to Galaxy dataset collections, or resolve tool wrappers against Tool Shed registries.

The casting pipeline compiles these Molds into executable agent skills tailored for modern agent platforms. By assembling atomic skills into ordered conversion pipelines---such as \texttt{paper-to-galaxy}, \texttt{nextflow-to-galaxy}, and \texttt{cwl-to-galaxy}---agents methodically ingest scientific literature or external code repositories and synthesize validated Galaxy workflows in \texttt{gxformat2}.

Deterministic validation guarantees reliability throughout the compilation loop. At each step, the \texttt{gxwf} validation engine verifies graph topology, step connectivity, and tool state against official Galaxy schemas and Intergalactic Workflow Commission exemplars. By grounding generative agents in a formal compiler architecture, Workflow Foundry transforms external scientific literature into verifiable, executable community assets. 

\section{Our System in Practice}

To evaluate our architecture across real-world biological domains, we executed three distinct investigations highlighting diverse analytical scenarios and computational scales. First, we reproduced a published spatial transcriptomics benchmark from a recent study on interactive research agents \cite{miao2026}. Second, we conducted an autonomous, structure-aware phylogenomics investigation of an antigenic gene family in a eukaryotic parasite. Finally, we performed census-scale emergence dating across 42 high-priority pathogen cohorts.

\subsection{Reproducing Spatial Transcriptomics Analysis from Published Literature}

Single-cell spatial transcriptomics maps gene expression directly within tissue architecture, but measuring whole transcriptomes in situ remains challenging. To overcome physical multiplexing limits, algorithms predict unmeasured spatial expression from paired single-cell RNA-seq references. However, downstream biological discoveries require rigorous uncertainty quantification. Recently, Miao et al. \cite{miao2026} evaluated their Paper2Agent system by predicting spatial expression of \textit{Acta2} (smooth muscle $\alpha$-actin) across 3,405 cells in the mouse somatosensory cortex and calculating conformal prediction intervals using the TISSUE algorithm \cite{sun2024}. We asked whether an autonomous agent could reproduce this published analysis on Galaxy cyberinfrastructure, resolve data provenance ambiguities, and scale the workflow from a tutorial subset to a full reference dataset.

The investigation was directed autonomously by Orbit on UseGalaxy.org. When inspecting the published assets, Orbit uncovered a critical provenance ambiguity: the analysis in Extended Data Figure 1C of Miao et al. \cite{miao2026} did not derive from the full Zenodo Dataset 15 archive (5,613 reference cells $\times$ 30,528 genes), but instead utilized an unannotated 1,000-cell tutorial subset bundled with the software repository. Orbit resolved this discrepancy and benchmarked both datasets. Because TISSUE was absent from the Galaxy Tool Shed, Orbit authored and registered an unprivileged User-Defined Tool (\texttt{tissue\_spatial\_prediction}, container \texttt{quay.io/biocontainers/squidpy:1.5.0}) configured for multi-core execution across four allocated cores. Orbit then synthesized a validated Galaxy workflow that chained paired expression preprocessing, SpaGE spatial domain adaptation, cell-cell spatial graph construction, and stratified conformal uncertainty calibration.

On the 1,000-cell benchmark dataset, the Galaxy execution reproduced the published results with high fidelity (Fig.~\ref{fig:spatial_comparison}). The empirical coverage reached 86.46\%. This result matches the published value of approximately 86.5\% at nominal 77\% coverage ($\alpha = 0.23$). Spatial uncertainty distributions aligned closely with published values: mean $\log(1 + \text{PI Width})$ was 2.0621 compared to the published value of $\approx 2.06$, and the 95th percentile was 2.3552 compared to $\approx 2.35$. Cross-environment validation between local execution and the remote Galaxy UDT matched to machine precision ($r = 1.0000$, maximum difference $< 10^{-15}$).

Orbit then scaled the workflow to the complete Zenodo Dataset 15. Integrating all 5,613 reference cells increased the Pearson correlation between predicted and measured \textit{Acta2} expression threefold. Correlation improved from $r = 0.0861$ on the tutorial subset to $r = 0.2553$ on the full dataset. Conformal coverage remained well-calibrated at 85.61\%. The expanded reference preserved anatomical uncertainty boundaries while refining spatial resolution. Extending this analysis to a 10-fold cross-validation across all 33 measured spatial genes confirmed conservative coverage bounds across nominal thresholds (79.05\% empirical coverage at nominal 77\%, and 81.33\% at nominal 80\%). All analytical artifacts generated during this reproduction are permanently archived and accessible on UseGalaxy.org (Supplementary Table~\ref{tab:case1_artifacts}).

\subsection{Heavy-Weight Model Orchestration and Structure-Aware Phylogenomics}

The \textit{Plasmodium} interspersed repeat (\textit{pir}) multigene family, termed \textit{vir} in \textit{Plasmodium vivax}, encodes exported surface adhesins that mediate antigenic variation and host immune evasion \cite{jackson2026}. Initial sequence-based classifications based on the incomplete, short-read Salvador-I reference defined ten to twelve subfamilies, designated VIR-A through VIR-L \cite{carlton2008, lopez2013}. Subsequent long-read assemblies expanded this repertoire fourfold, identifying over 1,000 \textit{vir} genes per genome across isolates from Indonesia (PvP01) \cite{auburn2016} and Peru (PvPAM) \cite{demeulenaere2023}. Rapid sequence diversification drops amino acid identity into the twilight zone, reaching a median of only 32\% across homologs. Standard sequence alignment fails at these distances. Markov clustering fractures the repertoire into 146 artificial subfamilies. Because over 600 South American VIR proteins lacked one-to-one sequence orthologs in Southeast Asian genomes, earlier studies hypothesized rapid, lineage-specific continental radiation. Yet crystallographic structures show that divergent PIR ectodomains share a conserved four-helix bundle fold despite extreme loop hyper-variability (PDB 6ZYV) \cite{harrison2020}. We asked whether an autonomous agent could orchestrate structure-aware phylogenomics on public cyberinfrastructure across long-read assemblies from Indonesia, Thailand, and Peru to test whether structural clustering unifies this fragmented repertoire and whether antigenic diversity reflects recent continental radiation or ancient global panmixia.

The investigation proceeded autonomously on UseGalaxy.org. The agent screened candidate loci against Pfam PF05795 across the three continental genomes using Galaxy's HMMER tool to identify VIR-like genes. Because standard sequence tools could neither embed nor align structural alphabets, the agent authored and registered ten unprivileged User-Defined Tools. To predict three-dimensional structural alphabets (3Di) directly from sequences without expensive coordinate modeling, the agent packaged the 4.4-gigabyte ProstT5 transformer model with Foldseek. The agent specified GPU resource allocations directly within the tool schema to route execution to an NVIDIA A100 node on ACCESS-CI cyberinfrastructure. When standard FoldMason containers failed from missing compilation flags, the agent diagnosed execution logs and built a functional container image (\nolinkurl{quay.io/nekrut/foldmason-prostt5:4.dd3c235-cpu}). The finalized workflow linked six-frame pseudogene translation, 3Di structural clustering, lockstep amino acid and structural multiple alignment, synteny evaluation against 5,120 housekeeping genes, and partitioned maximum-likelihood phylogenetics.

Structural clustering halved repertoire complexity (Fig.~\ref{fig:vir_reconstruction}a). Foldseek collapsed 2,592 VIR proteins from 146 sequence subfamilies into 73 structural classes. The dominant structural superfamily, FS\_001, absorbed 1,197 proteins (46\% of the total repertoire) and merged 89 sequence subfamilies that previous methods treated as unrelated lineages. Structural classes proved universally shared across geography. Over 97.3\% of VIR proteins resided in clusters containing representatives from Indonesia, Thailand, and Peru. Lineage-unique clusters accounted for only 2\% of sequences. Maximum-likelihood structural phylogenetics of 338 FS\_001 representatives demonstrated complete geographic interleaving across continents (Fig.~\ref{fig:vir_reconstruction}b). Tip-label parsimony tests treating genome of origin as a discrete character confirmed that the observed geographic distribution was indistinguishable from random permutation ($p = 0.55$). Diversification predated continental separation. Chromosomal mapping revealed that 64.5\% of VIR loci reside within the outer 10\% of chromosomal termini. This subtelomeric clustering creates an evolutionary engine for ectopic exchange that scrambles flanking gene order while preserving the structural core. Sequence alignment alone misidentifies orthologs. Out of 194 reciprocal best-hit pairs between Thailand and Peru within FS\_001, only eleven maintained flanking microsynteny against the housekeeping backbone. An automated verification suite validated 77 independent quantitative claims against raw outputs, achieving complete concordance (77/77 PASS).

\subsection{Emergence Dating Across 42 High-Priority Pathogens}

Accurately estimating pathogen emergence dates and evolutionary rates is central to genomic epidemiology. Canonical divergence time estimation relies on Bayesian Markov chain Monte Carlo frameworks implemented in BEAST \cite{suchard2018}. These models explore genealogical trees, branch lengths, and demographic priors simultaneously. Computational scaling breaks down on large cohorts. Joint Bayesian inference across thousands of viral genomes demands weeks of high-performance cluster runtime to achieve MCMC convergence. To eliminate this computational bottleneck, we recently developed HyphAeon, an analytical framework that extracts evolutionary velocities directly from sequence distance geometry and continuous manifold embeddings without reconstructing phylogenetic trees \cite{pond2026hyphaeon}. Here, we asked whether an autonomous agent could orchestrate the systematic re-analysis of emergence dates across 42 published high-priority pathogen cohorts on Galaxy cyberinfrastructure to determine whether tree-free manifold dating achieves numerical concordance with established Bayesian benchmarks across diverse genomic scales and evolutionary regimes.

The investigation proceeded autonomously on UseGalaxy.org. The agent compiled 42 published reference cohorts spanning diverse viral and bacterial epidemics, including Ebola, SARS-CoV-2, Zika, Dengue, Chikungunya, Mpox, and \textit{Yersinia pestis}. Original author XML files were archived to guarantee byte-level provenance. The agent authored and registered two unprivileged User-Defined Tools. The first tool, \texttt{chronaeon\_batch\_preparator}, validated XML syntax, extracted aligned nucleotide matrices, and structured inputs into synchronized 42-element Galaxy dataset collections. The second tool, \texttt{chronaeon\_cohort\_analysis}, executed tree-free Date regression, non-linear spline clock fitting, manifold clustering, and leave-one-out cross-validation. Galaxy mapped all 42 cohort jobs concurrently across distributed high-performance nodes.

All 42 reference cohorts completed successfully on UseGalaxy.org with a median execution time of 3.41 seconds per study (Fig.~\ref{fig:chronaeon_42cohorts}). Rather than relying on commodity workstations, the agent dispatched these manifold computations to dedicated high-performance nodes on ACCESS-CI cyberinfrastructure equipped with NVIDIA A100 GPUs (80GB VRAM) and AMD EPYC processors. Published Bayesian MCMC runs required tens to hundreds of CPU-hours on identical alignments. In the 2014 Sierra Leone Ebola outbreak (196 taxa), tree-free dating estimated a root date of 2014.23 (95\% CI: [2014.17, 2014.27]) with a cross-validation mean error of 26.4 days, matching the published BEAST root of 2014.20 ([2014.10, 2014.30]) \cite{gire2014genomic}. For the 2014--2016 West African Makona lineage (1,610 taxa), the inferred root of 2013.81 ([2013.74, 2013.86]) agreed closely with published BEAST estimates (2013.98, [2013.79, 2014.15]) \cite{dudas2017virus}. Tree-free dating also resolved the SARS-CoV-2 Gamma emergence at 2020.71 (BEAST: 2020.87, error: 17.0 days).

Comparative outcomes organized across a four-part analytical taxonomy. Category I comprised unimodal concordance (19 cohorts, 45.2\%), where active longitudinal sampling under stable substitution rates yielded direct convergence with BEAST credible intervals. Category II captured genealogical scope mismatches (9 cohorts, 21.4\%). In these datasets, unpartitioned distance regression evaluated the crown of sampled sequences, whereas published studies conditioned on tree priors to date deep roots or introductions. Applying AutoClock normalized Laplacian spectral bisection ($K^*$) decoupled localized transmission crowns without taxonomic labels. Spectral deconvolution recovered the published 1960 mode in Dengue-3 within 1.6 years (1961.62 vs 1960.0) \cite{taylorsalmon2024travel}, matched the 2007 European introduction in African swine fever (2006.53 vs 2006.15), and isolated the acute 2005 island wave in Chikungunya La R{\'e}union (2005.10 vs 2004.80). Reconciling genealogical scope elevated benchmark concordance to 59.5\% (25 of 42 cohorts), reaching $R = 0.86$ ($R^2 = 0.74$) across modern surveillance datasets. Category III captured regularization differences (8 cohorts, 19.0\%). In datasets with narrow temporal depth or mutational sparsity, tree priors perform heavy shrinkage in Bayesian MCMC, manufacturing narrow intervals. Distance geometry computes exact finite-sample bounds via Fieller's theorem \cite{fieller1954some}. When temporal signal is indistinguishable from noise ($g \ge 1.0$), Fieller intervals expand to infinity, alerting researchers that data lack longitudinal signal. Category IV captured lineage heterotachy and rate mixtures (6 cohorts, 14.3\%), where AutoClock separated asynchronous sub-epidemics.

\section{Discussion}

The integration of autonomous artificial intelligence into empirical science represents a critical turning point. If autonomous agents continue to operate as disembodied conversationalists inside private local environments, computational science will fragment into an unobservable collection of irreproducible, post-verifiable claims. By providing artificial intelligence with an open, distributed computational body, our architecture establishes a new paradigm: verifiable agentic science governed by provenance by construction.

Scientific progress relies on the ability of independent researchers to inspect, challenge, and replicate computational findings. In conventional agent workflows, reproducibility depends entirely on post-hoc human discipline---an assumption that consistently fails in practice. Domain researchers interacting with conversational agents rarely record intermediate commands, pin operating system dependencies, or preserve raw data transformations.

Our architecture transfers the burden of reproducibility from human discipline to computational infrastructure. By executing analyses across Galaxy cyberinfrastructure, every analytical step is recorded upon an immutable directed acyclic graph. Tool versions, container digests, parameter values, and intermediate datasets are sealed in a permanent provenance ledger. This record is not an optional export---it is the physical mechanism through which compute occurs. Consequently, scientific claims generated through this framework carry complete execution lineage, ensuring that autonomous discoveries remain verifiable by the global scientific community.

The computational demands of frontier artificial intelligence threaten to centralize scientific discovery within well-funded commercial institutions. When automated research requires private compute clusters and proprietary cloud platforms, independent academic investigators are systematically excluded from high-throughput discovery.

We demonstrate that public, federally supported cyberinfrastructure can serve as the foundational execution surface for modern artificial intelligence. By pairing open foundation models and universal protocols with the Galaxy platform, we democratize autonomous science. A researcher at an under-resourced institution, equipped only with a standard laptop, can direct autonomous agents that orchestrate distributed supercomputing allocations, query petabyte-scale reference archives, and execute high-throughput pipelines across national high-performance clusters. Preserving the public scientific commons in the era of artificial intelligence is not merely an ethical priority---it is an infrastructural necessity for ensuring universal participation in scientific discovery.

Looking forward, coupling autonomous reasoning to open cyberinfrastructure establishes the foundation for a collaborative, planetary-scale scientific network. In this ecosystem, published workflows, curated reference databases, and execution engines communicate through standardized machine-readable protocols. Autonomous agents will not operate as isolated local assistants, but as distributed co-investigators capable of querying global workflow repositories, verifying analytical findings across independent compute clusters, and synthesizing collective biological knowledge. Grounding artificial intelligence in open, verifiable infrastructure ensures that the automated science of the coming decade remains transparent, reproducible, and universally accessible.

\section*{Methods}

\subsection*{Galaxy Model Context Protocol and Modular Skills}
Agents interact with computational infrastructure through the Galaxy Model Context Protocol server (\texttt{galaxy-mcp}) \cite{galaxymcp2026}. The Model Context Protocol establishes an open standard for tool execution and data inspection. Rather than allowing agents to execute arbitrary local shell commands, the server provides forty-four structured endpoints. These endpoints enable agents to search tool registries, inspect dataset collections, launch workflows, and monitor execution states through standard input-output streams or remote HTTP connections. The server is implemented in Python utilizing the official BioBlend library to communicate with the Galaxy REST API. Transport mechanisms include standard input-output (stdio) for local CLI integration and streamable HTTP for web and remote clients. Authentication occurs through long-lived Galaxy API keys or OAuth2 token exchanges. The server provides structured error handling and schema validation across all parameter endpoints.

Domain expertise is provided through modular skill packages \cite{galaxyskills2026}. These skills teach language models standard bioinformatics conventions. Skills guide tool discovery, parameter selection, and collection manipulation idioms. For complex multi-step pipelines, Workflow Foundry skills compile validated workflow templates directly into agent memory \cite{foundry2026}. By separating operational skills from the underlying compute runtime, the framework ensures that agents execute verified analytical procedures rather than generating unvalidated guesses.

\subsection*{User-Defined Tool Architecture}
User-Defined Tools are authored in YAML adhering to the \texttt{GalaxyUserTool} class definition. The tool wrapper specifies a mandatory container image hosted on public registries (Quay.io, Docker Hub), typed input parameters, declared output datasets, and an execution command. Commands are templated using sandboxed ECMAScript evaluation executed inside an isolated V8 runtime. Output files are claimed from the working directory through \texttt{from\_work\_dir} designations or dynamic dataset discovery patterns.

\subsection*{Orbit Workbench and Execution Guard}
Orbit is constructed as an Electron desktop application powered by a headless agent runtime built as an extension on Pi.dev. The runtime manages session context, system prompts, and tool registration. The execution guard intercepts tool calls via internal lifecycle hooks, classifying actions across model tiers, path security, and shell hazard. Local file writes are strictly confined to the workspace root using realpath resolution. Remote Galaxy jobs are tracked through YAML invocation blocks embedded within \texttt{notebook.md}, which are updated via background polling and asynchronous event handlers.

\subsection*{Workflow Foundry Casting Pipeline}
The Workflow Foundry compiler is implemented in TypeScript and Node.js. Molds are authored as Markdown documents carrying structured Zod-validated YAML frontmatter declaring pattern dependencies, manual references, and input-output schemas. The casting pipeline compiles Molds into target-specific agent skills. Synthesized workflows are validated statically using the \texttt{gxwf} validation engine, which verifies graph topology, step connectivity, and tool state against official Galaxy XML schemas and IWC exemplars.
