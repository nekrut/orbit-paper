## Abstract

Frontier artificial intelligence models promise to accelerate scientific discovery by automating hypothesis formulation, experimental design, and computational code execution across complex biological domains. Yet adoption in the life sciences remains stalled. Researchers face a fundamental deficit of trust and computational scale. When investigators run autonomous agents on local machines, computations vanish into opaque terminal shells. Scripts remain unversioned. Intermediate files are overwritten without a record. Moreover, large biological datasets quickly overwhelm consumer hardware. We resolve this dilemma. Here we introduce an open agentic architecture that couples autonomous language models directly to public Galaxy cyberinfrastructure. This environment establishes computational transparency and provenance by construction. To direct long-horizon investigations, we develop Orbit, an opinionated research workbench that binds human intent, planning checkpoints, and remote cloud invocations into an interactive, living research notebook. Complementing this workbench, the Workflow Foundry compiles scientific literature into schema-validated workflows without manual scripting. Unprivileged User-Defined Tools allow agents to orchestrate containerized commands and heavy deep-learning models across national supercomputing allocations without administrative friction. By embedding provenance and reproducibility directly into the execution environment, our architecture transforms autonomous language models into disciplined, transparent, and verifiable scientific collaborators.

# Introduction

Across all scientific domains, LLM-powered agents formulate hypotheses, author analytical pipelines, execute code, and draft complete research manuscripts [1–6]. Recognizing these capabilities, academic and corporate laboratories have created specialized, domain-specific environments such as Co-Scientist to coordinate autonomous research [7]. Yet domain platforms cannot match the rapid development velocity, model optimizations, and tooling ecosystems powering general-purpose agent harnesses from the major artificial intelligence providers—Google, Anthropic, and OpenAI. At our own research institutions, we have watched numerous graduate students, postdocs, and PIs (even those who are AI-averse) adopt these agentic tools, become hooked, and stop analyzing data in any other way. This quickly makes general agent harnesses the primary working environment for modern computational research.

This rapidly widening use of agentic tools in science is equally thrilling and terrifying. The thrill comes from the speed and seemingly unlimited number of possibilities that suddenly became available to any researcher. The terror comes from a completely new set of scientific challenges that are not immediately apparent but will become severe as agentic science becomes the new norm. First, provenance tracking is largely absent. As unsupervised agents iterate, they generate ephemeral shell scripts, unversioned intermediate tables, and temporary scratch files. These ad-hoc artifacts vanish as soon as the session closes, and few have the proper version control skills and discipline to keep the full record. Scientific research requires that every analytical operation, tool version, and parameter choice be formalized into an immutable, shareable record so that colleagues can inspect, verify, and reproduce the complete computational trajectory. Second, autonomous agents require community-curated skills and standardized, high-quality bioinformatics tools. Rather than improvising custom scripts from unvetted online snippets, agents must make analytical decisions guided by verified computational protocols and validated tool specifications that function across different agent harnesses. Third, the agentic revolution does not change the need for infrastructure access. While modern laptops handle exploratory scripting effectively, production biological workflows—such as large-scale genome assembly, analyses of large multi-sample datasets, or deep learning inference—demand high-performance computing clusters with hundreds of processor cores, massive memory allocations, and dedicated hardware accelerators. Installing autonomous agent harnesses directly onto shared institutional supercomputers violates facility security policies and remains administratively unsustainable.

For over twenty years, the Galaxy platform has provided open, reproducible cyberinfrastructure to life scientists worldwide [8]. It now serves as an ideal agentic plane to address these challenges. First, it provides a universal compute abstraction that schedules complex, containerized analytical workloads across heterogeneous institutional clusters, national supercomputing allocations, and commercial clouds without requiring interactive login credentials, private keys, or command-line administrative access. Second, Galaxy's web interface and history system serve as an ideal artifact display mechanism. Every analytical step, parameter choice, and intermediate dataset is recorded within an immutable directed acyclic graph that investigators and their collaborators can inspect, audit, visualize, and re-execute with a single click. Third, the platform supplies the definitive scientific knowledge base. The Intergalactic Utilities Commission maintains thousands of vetted, containerized tool wrappers, the Intergalactic Workflow Commission curates standardized analytical pipelines, and the Galaxy Training Network provides hundreds of peer-reviewed, step-by-step procedural tutorials. Finally, the Workflow Foundry translates external bioinformatics knowledge—including Nextflow pipelines and published methods—into structured agentic skills that guide autonomous execution across Galaxy cyberinfrastructure [9]. Galaxy grounds autonomous language models in transparent, reproducible, and vendor-agnostic scientific infrastructure.

Here we demonstrate the utility of our platform across 44 empirical evaluations, reproducing 43 published cohorts across 38 studies and conducting a novel large-scale analysis of antigenic variation in malaria. In spatial transcriptomics, an agent reproduces published conformal uncertainty predictions to numerical precision, then scales the workflow across an expanded reference cohort. In structural phylogenomics, the agent authors unprivileged User-Defined Tools to execute deep-learning protein language models on remote GPU clusters. This structural clustering collapses 146 fragmented *Plasmodium vivax* antigen subfamilies into 73 shared classes. In genomic epidemiology, the platform automates emergence dating across 42 published pathogen epidemics. Tree-free manifold geometry matches compute-intensive Bayesian benchmarks in seconds per study. Across all three investigations, every analytical step, containerized tool, and intermediate dataset is documented as an immutable history on public cyberinfrastructure.

## Advanced models propose vastly different analysis plans ...

Today many biological researchers discover how seemingly easy it is to conduct data analysis with agents. Suppose a student is given a task of analyzing RNA-seq data by an advisor. The student is adventurous enough to try to use one of the widely advertised agents. The student uploads data, explains to the agent the experimental design, and asks it to propose an analysis plan (Note that planning is not a widely adopted discipline in biomedical research and that appropriate use of agents requires significant changes to the present curriculum.). How does the student know that the proposed plan is good? How would the student choose among possibilities proposed by an agent? To illustrate this problem we asked 30 agents (10 for each of Anthropic, OpenAI, and Google, respectively) to propose reanalysis plans for a paper (because we know what the expected outcome should be) describing a published transcriptomic study (PMC12804731) [10]. The agents generated 18 proposed workflows (Figure [fig:agent_trajectories]). While differences like workflow engines were purely operational, eleven of these plans would produce different scientific outcomes if executed. They made conflicting biological choices across reference genomes, read strandedness, and statistical sample pooling. These choices would also result in dramatic changes in resource requirements, as shown in Supplementary Table [tab:agent_resources]. 

## ... and leave a dusty trail of intermediats.

## Galactic plane: Agent, Skills, UI, Infrastr



Agentic data analysis operates as a closed loop between a remote language model and a local agent harness. The model runs remotely. It is hosted by commercial providers such as Google, Anthropic, or OpenAI, or executed as an open-weight foundation model across institutional supercomputing clusters. The agent harness runs on the user's computer. It manages session memory, communicates with the model across programmatic interfaces, and executes concrete operations on the operating system. An investigator provides a natural language prompt. The model returns structured instructions. The agent harness acts upon them. It writes novel parsing scripts, downloads existing software packages, uncompresses raw archives, or queries external repositories through their respective application interfaces. As commands finish, the agent harness returns terminal logs, exit codes, and intermediate files to the model for iterative error diagnosis and next-step planning. Two mechanisms provide guardrails that constrain free-wheeling agent behavior: skills and Model Context Protocol (MCP) servers. Skills are simple text files defining procedural rules. Model Context Protocol servers supply formal programmatic functions that tell agents how to interact with external environments. Together, these guardrails channel model reasoning into specific, verifiable operations.

In our architecture, an investigator drives scientific analysis through an autonomous agent. The framework is agent agnostic. Researchers can operate from any general-purpose agent runtime, including Claude Code, OpenAI Codex, Google Antigravity, Open Code, or Pi.dev [11]. To support life scientists directly, we also developed Orbit, a specialized research workbench described in detail below [12]. Orbit incorporates domain capabilities that simplify remote execution, enforce structured record-keeping, and streamline the agentic utilization of Galaxy cyberinfrastructure.

The overall operational flow requires only two prerequisites (Figure [fig:architecture]). First, the investigator needs a Galaxy account. Registration is free and provides a personal API key, allowing the agent to drive Galaxy services programmatically without administrative friction. Second, the user needs access to a large language model. This can be a commercial frontier model, an open-weight model from independent providers, or a local model hosted on the user's workstation. The agent bridges to the Galaxy platform through two complementary mechanisms: modular skills and a Model Context Protocol (MCP) server [13, 14]. Skills supply procedural domain intelligence, teaching the model standard conventions for biomedical data analysis. The Galaxy MCP server equips the agent with structured programmatic endpoints, instructing it how to query datasets, execute tools, and monitor computational state.

An investigation begins interactively. The user provides a natural language prompt defining a scientific objective. The agent then formulates an initial analytical plan. The plan lays out a sequence of tool executions designed to transform raw biological inputs into final results. Tools in this execution chain fall into two categories:

- **Pre-existing Galaxy tools:** Galaxy maintains thousands of community-curated, peer-reviewed bioinformatics tools spanning genomics, transcriptomics, proteomics, and structural biology [8].
- **Novel or missing tools:** Specialized operations occasionally require software not yet present in the Galaxy catalog, which the agent either authors dynamically as custom wrappers or imports from external container registries.

Before any heavy computation begins, the investigator reviews and approves the drafted plan. This conversational checkpoint enables researchers to discuss unfamiliar analytical steps with the agent, explore alternatives, and align tool parameters with biological intent.

Once the plan is approved, the agent dry-runs the analytical pipeline. It extracts a small subset of data to test the end-to-end execution path rapidly. Whenever possible, this initial validation executes directly on the user's local machine. Local execution allows rapid debugging without consuming shared cloud allocations. However, local prototyping is skipped under two conditions. First, tasks involving heavy tools—such as deep learning models requiring large neural network weights—cannot be installed or executed on standard workstations. Second, restricted operating environments, such as Windows systems lacking native POSIX environments or container virtualization, prevent local execution. In these situations, the agent bypasses local prototyping and conducts verification directly on remote cyberinfrastructure.

With the workflow verified, the agent transitions to remote execution on Galaxy:

- **Data upload:** The agent uploads input datasets, reference annotations, and metadata collections into the user's Galaxy account.
- **Tool invocation and extension:** It invokes pre-installed Galaxy tools or provisions novel utilities dynamically using User-Defined Tools (UDTs) [15].
- **Workflow assembly and validation:** The agent links computational stages into a formal Galaxy workflow definition. It binds inputs and outputs across collection structures, validates directed graph topology, and verifies schema conformance before execution.
- **Step-by-step execution:** It executes the analytical plan sequentially, passing intermediate dataset collections between stages.
- **Self-healing execution:** When an individual step encounters a failure, the agent inspects standard error logs, identifies parameter misconfigurations or format mismatches, modifies the execution command, and reruns the step until it completes cleanly.
- **Result generation:** It synthesizes final outputs, including quality metrics, statistical tables, and publication-ready visualizations.


As mentioned earlier, this entire process can be driven from any agent and works well from command-line environments such as Claude Code. Yet the terminal paradigm may still be unfamiliar to bench biomedical researchers. To ease this transition, we built Orbit [12]. Orbit is a dedicated desktop application that simplifies researcher interaction with autonomous agents. It functions across model tiers, driving commercial frontier models, open-weight alternatives, and locally hosted models via Ollama. Unlike generic programming assistants, Orbit embeds deep Galaxy domain intelligence and enforces disciplined scientific usage patterns. Central to this discipline is the living research notebook. As an investigation unfolds, the notebook records a continuous narrative of the analysis: initial hypotheses, tool parameters, execution rationale, and analytical artifacts such as figures, charts, and summary tables. At the conclusion of an investigation, Orbit deposits this notebook directly into the user's Galaxy history. While external agent runtimes can perform this deposit through MCP calls, Orbit maintains the notebook as an always-visible, primary canvas. The notebook becomes the permanent living memory of the investigation. It preserves complete computational provenance. Independent investigators can inspect and share this record, while subsequent agents can ingest it to validate, reproduce, or extend previous findings.

## Galaxy for supercharging agents
Galaxy is an integrated analysis environment that pairs a web-based interface with distributed public computing infrastructure [8]. In the United States, Galaxy provides direct access to national research cyberinfrastructure coordinated through the ACCESS program (Advanced Cyberinfrastructure Coordination Ecosystem: Services & Support). Through this unified interface, tools run transparently across national supercomputing centers, including the Texas Advanced Computing Center (Stampede3, Vista, and Corral), the Pittsburgh Supercomputing Center (Bridges-2), the San Diego Supercomputer Center (Expanse), Purdue University (Anvil), and Indiana University (Jetstream2). Centralized dataset storage at Penn State manages petabytes of user data, while reference databases synchronize globally across the CVMFS network.

Galaxy does not treat compute nodes as interchangeable commodity servers. For every tool in its catalog, the platform determines how to schedule appropriate computational resources. Galaxy achieves this through Total Perspective Vortex, a dynamic resource router, and Pulsar, a remote job execution engine that dispatches tasks without requiring a shared filesystem. Resource routing adapts to the physical requirements of the assay:

- **High-throughput parallel tasks:** Embarrassingly parallel jobs, such as raw sequence quality control and read mapping, route to multi-core compute nodes configured with 32 to 128 processor cores.
- **Memory-intensive computations:** Tasks requiring massive memory, including de novo genome assembly and large k-mer indexing, route to specialized high-memory nodes equipped with terabytes of RAM.
- **Accelerated models:** Deep-learning workflows, structural predictors, and language models route to dedicated GPU clusters powered by NVIDIA hardware accelerators.

When scheduling each job, Galaxy evaluates dataset dimensions and historical execution metrics [16]. By analyzing past walltimes and memory footprints, the platform dynamically predicts resource consumption and adjusts queue reservations accordingly.

Autonomous agents cannot use this national cyberinfrastructure on their own. Institutional high-performance computing centers cannot grant autonomous agents unrestricted SSH credentials, interactive shell access, or raw batch scheduler privileges. Unsupervised agents risk saturating shared filesystems, exhausting project allocations, and triggering security hazards. Galaxy resolves this impasse by acting as a middle layer between autonomous reasoning and high-performance computing. Rather than managing Slurm scripts, staging files across remote clusters, or troubleshooting local environment modules, the agent interacts with Galaxy through a structured REST API and the Model Context Protocol [13]. Galaxy validates each request, verifies tool parameters, isolates dependencies within container images, and routes the execution across national clusters. The agent receives a clean, predictable execution interface.

This architecture scales because Galaxy is engineered for high-throughput production. The platform is not a prototype built for demonstration. Worldwide, Galaxy supports over 650,000 registered researchers. Public instances process hundreds of thousands of jobs every month, with the UseGalaxy national infrastructure alone executing approximately 2,000,000 analysis jobs monthly. Galaxy has operated continuously at this scale for two decades. Because the platform natively handles concurrent execution, queue failover, and massive multi-tenant data movement, it easily absorbs the intensive demands of autonomous AI agents. Yet real-world biological workflows often require custom software utilities absent from pre-installed tool catalogs. For these specialized analytical steps, the architecture relies on User-Defined Tools.

## Extensibility via User-Defined Tools

All global Galaxy instances contain thousands of curated tools. Historically, however, tool installation required administrative privileges. While central curation guarantees software quality and reproducibility, it creates friction when an analysis requires custom data-formatting scripts or novel utilities absent from official catalogs. User-Defined Tools (UDTs) provide dynamic extensibility on public infrastructure [15]. Introduced in Galaxy 26.1, UDTs allow unprivileged users and autonomous agents to register and run custom tools dynamically. A UDT is declared as a compact YAML specification that pairs an immutable container image with typed inputs and an isolated command template. Because templates evaluate using sandboxed ECMAScript rather than arbitrary host scripts, custom tools execute safely on shared supercomputing clusters.

UDTs span a broad spectrum of computational complexity. At one end, an agent can author a lightweight UDT in seconds to convert unusual tabular formats, filter metadata, or glue disparate workflow steps together. At the opposite end, UDTs orchestrate heavy foundation models requiring dedicated GPU acceleration. Later in this manuscript, we demonstrate this capability in our *Plasmodium vivax* case study. There, the agent authors custom UDTs that route 4.4-gigabyte protein language models directly to NVIDIA A100 GPUs on national supercomputers, executing complex structural alignments without manual system administration.

## Living Research Notebooks and Shared Provenance

Every completed analysis yields three complementary artifacts: an executable Galaxy workflow, a structured Galaxy history, and a living research notebook. The Galaxy workflow encapsulates the parameterized directed acyclic graph. It decouples the analytical protocol from specific sample instances. This separation enables immediate re-execution across new cohorts or high-throughput batch scaling. While the Galaxy history preserves physical data lineage and intermediate outputs, the research notebook captures the epistemic narrative. Structured similarly to an `AGENTS.md` record, the notebook documents the complete scientific context: initial hypotheses, biological motivations, human review checkpoints, and quantitative interpretations.

This triad establishes complete computational provenance. Rather than receiving an isolated PDF report with static figures, independent researchers receive the entire experimental fabric. Galaxy workflows, execution histories, living notebooks, and containerized tool definitions can be published, cited, and shared via persistent identifiers. Collaborators can inspect every intermediate dataset, examine why specific parameters were chosen, or re-execute the complete pipeline on public computing resources with a single click. By coupling autonomous agents to open infrastructure, biological discovery becomes fully transparent, verifiable, and reproducible.

## Compiling Scientific Procedures with Workflow Foundry

When large language models attempt to author complex scientific pipelines directly from unstructured prompts, they encounter recurring failure modes. Models hallucinate nonexistent tool identifiers, drop version revision suffixes, fabricate unsupported parameter flags, and generate syntax that workflow parsers reject immediately. Conventional prompt engineering and hand-authored instructions degrade quickly as software ecosystems evolve.

We address this limitation through Workflow Foundry, a specialized compiler that translates computational procedures into validated agent skills [9]. Rather than treating workflow construction as an unconstrained generative task, the Foundry decomposes scientific translation into modular, schema-enforced units called Molds. Each Mold specifies an atomic transformation step. Typical Molds extract input parameter schemas from published prose, map Nextflow process channels to Galaxy dataset collections, or resolve tool wrappers against Tool Shed registries.

The casting pipeline compiles these Molds into executable agent skills tailored for modern agent platforms. By assembling atomic skills into ordered conversion pipelines—such as `paper-to-galaxy`, `nextflow-to-galaxy`, and `cwl-to-galaxy`—agents methodically ingest scientific literature or external code repositories and synthesize validated Galaxy workflows in `gxformat2`.

Deterministic validation guarantees reliability throughout the compilation loop. At each step, the `gxwf` validation engine verifies graph topology, step connectivity, and tool state against official Galaxy schemas and Intergalactic Workflow Commission exemplars. By grounding generative agents in a formal compiler architecture, Workflow Foundry transforms external scientific literature into verifiable, executable community assets. 

# Our System in Practice

To evaluate our architecture across real-world biological domains, we executed three distinct investigations highlighting diverse analytical scenarios and computational scales. First, we reproduced a published spatial transcriptomics benchmark from a recent study on interactive research agents [17]. Second, we conducted an autonomous, structure-aware phylogenomics investigation of an antigenic gene family in a eukaryotic parasite. Finally, we performed census-scale emergence dating across 42 high-priority pathogen cohorts.

## Reproducing Spatial Transcriptomics Analysis from Published Literature

Single-cell spatial transcriptomics maps gene expression directly within tissue architecture, but measuring whole transcriptomes in situ remains challenging. To overcome physical multiplexing limits, algorithms predict unmeasured spatial expression from paired single-cell RNA-seq references. However, downstream biological discoveries require rigorous uncertainty quantification. Recently, Miao et al. [17] evaluated their Paper2Agent system by predicting spatial expression of *Acta2* (smooth muscle $\alpha$-actin) across 3,405 cells in the mouse somatosensory cortex and calculating conformal prediction intervals using the TISSUE algorithm [18]. We asked whether an autonomous agent could reproduce this published analysis on Galaxy cyberinfrastructure, resolve data provenance ambiguities, and scale the workflow from a tutorial subset to a full reference dataset.

The investigation was directed autonomously by Orbit on UseGalaxy.org. When inspecting the published assets, Orbit uncovered a critical provenance ambiguity: the analysis in Extended Data Figure 1C of Miao et al. [17] did not derive from the full Zenodo Dataset 15 archive (5,613 reference cells $\times$ 30,528 genes), but instead utilized an unannotated 1,000-cell tutorial subset bundled with the software repository. Orbit resolved this discrepancy and benchmarked both datasets. Because TISSUE was absent from the Galaxy Tool Shed, Orbit authored and registered an unprivileged User-Defined Tool (`tissue_spatial_prediction`, container `quay.io/biocontainers/squidpy:1.5.0`) configured for multi-core execution across four allocated cores. Orbit then synthesized a validated Galaxy workflow that chained paired expression preprocessing, SpaGE spatial domain adaptation, cell-cell spatial graph construction, and stratified conformal uncertainty calibration.

On the 1,000-cell benchmark dataset, the Galaxy execution reproduced the published results with high fidelity (Fig. [fig:spatial_comparison]). The empirical coverage reached 86.46%. This result matches the published value of approximately 86.5% at nominal 77% coverage ($\alpha = 0.23$). Spatial uncertainty distributions aligned closely with published values: mean $\log(1 + \text{PI Width})$ was 2.0621 compared to the published value of $\approx 2.06$, and the 95th percentile was 2.3552 compared to $\approx 2.35$. Cross-environment validation between local execution and the remote Galaxy UDT matched to machine precision ($r = 1.0000$, maximum difference $< 10^{-15}$).

## Heavy-Weight Model Orchestration and Structure-Aware Phylogenomics

The *Plasmodium* interspersed repeat (*pir*) multigene family, termed *vir* in *Plasmodium vivax*, encodes exported surface adhesins that mediate antigenic variation and host immune evasion [19]. Initial sequence-based classifications based on the incomplete, short-read Salvador-I reference defined ten to twelve subfamilies, designated VIR-A through VIR-L [20, 21]. Subsequent long-read assemblies expanded this repertoire fourfold, identifying over 1,000 *vir* genes per genome across isolates from Indonesia (PvP01) [22] and Peru (PvPAM) [23]. Rapid sequence diversification drops amino acid identity into the twilight zone, reaching a median of only 32% across homologs. Standard sequence alignment fails at these distances. Markov clustering fractures the repertoire into 146 artificial subfamilies. Because over 600 South American VIR proteins lacked one-to-one sequence orthologs in Southeast Asian genomes, earlier studies hypothesized rapid, lineage-specific continental radiation. Yet crystallographic structures show that divergent PIR ectodomains share a conserved four-helix bundle fold despite extreme loop hyper-variability (PDB 6ZYV) [24]. We asked whether an autonomous agent could orchestrate structure-aware phylogenomics on public cyberinfrastructure across long-read assemblies from Indonesia, Thailand, and Peru to test whether structural clustering unifies this fragmented repertoire and whether antigenic diversity reflects recent continental radiation or ancient global panmixia.

The investigation proceeded autonomously on UseGalaxy.org. The agent screened candidate loci against Pfam PF05795 across the three continental genomes using Galaxy's HMMER tool to identify VIR-like genes. Because standard sequence tools could neither embed nor align structural alphabets, the agent authored and registered ten unprivileged User-Defined Tools. To predict three-dimensional structural alphabets (3Di) directly from sequences without expensive coordinate modeling, the agent packaged the 4.4-gigabyte ProstT5 transformer model with Foldseek. The agent specified GPU resource allocations directly within the tool schema to route execution to an NVIDIA A100 node on ACCESS-CI cyberinfrastructure. When standard FoldMason containers failed from missing compilation flags, the agent diagnosed execution logs and built a functional container image (`quay.io/nekrut/foldmason-prostt5:4.dd3c235-cpu`). The finalized workflow linked six-frame pseudogene translation, 3Di structural clustering, lockstep amino acid and structural multiple alignment, synteny evaluation against 5,120 housekeeping genes, and partitioned maximum-likelihood phylogenetics.

Structural clustering halved repertoire complexity (Fig. [fig:vir_reconstruction]a). Foldseek collapsed 2,592 VIR proteins from 146 sequence subfamilies into 73 structural classes. The dominant structural superfamily, FS_001, absorbed 1,197 proteins (46% of the total repertoire) and merged 89 sequence subfamilies that previous methods treated as unrelated lineages. Structural classes proved universally shared across geography. Over 97.3% of VIR proteins resided in clusters containing representatives from Indonesia, Thailand, and Peru. Lineage-unique clusters accounted for only 2% of sequences. Maximum-likelihood structural phylogenetics of 338 FS_001 representatives demonstrated complete geographic interleaving across continents (Fig. [fig:vir_reconstruction]b). Tip-label parsimony tests treating genome of origin as a discrete character confirmed that the observed geographic distribution was indistinguishable from random permutation ($p = 0.55$). Diversification predated continental separation. Chromosomal mapping revealed that 64.5% of VIR loci reside within the outer 10% of chromosomal termini. This subtelomeric clustering creates an evolutionary engine for ectopic exchange that scrambles flanking gene order while preserving the structural core. Sequence alignment alone misidentifies orthologs. Out of 194 reciprocal best-hit pairs between Thailand and Peru within FS_001, only eleven maintained flanking microsynteny against the housekeeping backbone. An automated verification suite validated 77 independent quantitative claims against raw outputs, achieving complete concordance (77/77 PASS).

## Emergence Dating Across 42 High-Priority Pathogens

Accurately estimating pathogen emergence dates and evolutionary rates is central to genomic epidemiology. Canonical divergence time estimation relies on Bayesian Markov chain Monte Carlo frameworks implemented in BEAST [25]. These models explore genealogical trees, branch lengths, and demographic priors simultaneously. Computational scaling breaks down on large cohorts. Joint Bayesian inference across thousands of viral genomes demands weeks of high-performance cluster runtime to achieve MCMC convergence. To eliminate this computational bottleneck, we recently developed HyphAeon, an analytical framework that extracts evolutionary velocities directly from sequence distance geometry and continuous manifold embeddings without reconstructing phylogenetic trees [26]. Here, we asked whether an autonomous agent could orchestrate the systematic re-analysis of emergence dates across 42 published high-priority pathogen cohorts on Galaxy cyberinfrastructure to determine whether tree-free manifold dating achieves numerical concordance with established Bayesian benchmarks across diverse genomic scales and evolutionary regimes.

The investigation proceeded autonomously on UseGalaxy.org. The agent compiled 42 published reference cohorts spanning diverse viral and bacterial epidemics, including Ebola, SARS-CoV-2, Zika, Dengue, Chikungunya, Mpox, and *Yersinia pestis*. Original author XML files were archived to guarantee byte-level provenance. The agent authored and registered two unprivileged User-Defined Tools. The first tool, `chronaeon_batch_preparator`, validated XML syntax, extracted aligned nucleotide matrices, and structured inputs into synchronized 42-element Galaxy dataset collections. The second tool, `chronaeon_cohort_analysis`, executed tree-free Date regression, non-linear spline clock fitting, manifold clustering, and leave-one-out cross-validation. Galaxy mapped all 42 cohort jobs concurrently across distributed high-performance nodes.

All 42 reference cohorts completed successfully on UseGalaxy.org with a median execution time of 3.41 seconds per study (Fig. [fig:chronaeon_42cohorts]). Rather than relying on commodity workstations, the agent dispatched these manifold computations to dedicated high-performance nodes on ACCESS-CI cyberinfrastructure equipped with NVIDIA A100 GPUs (80GB VRAM) and AMD EPYC processors. Published Bayesian MCMC runs required tens to hundreds of CPU-hours on identical alignments. In the 2014 Sierra Leone Ebola outbreak (196 taxa), tree-free dating estimated a root date of 2014.23 (95% CI: [2014.17, 2014.27]) with a cross-validation mean error of 26.4 days, matching the published BEAST root of 2014.20 ([2014.10, 2014.30]) [27]. For the 2014–2016 West African Makona lineage (1,610 taxa), the inferred root of 2013.81 ([2013.74, 2013.86]) agreed closely with published BEAST estimates (2013.98, [2013.79, 2014.15]) [28]. Tree-free dating also resolved the SARS-CoV-2 Gamma emergence at 2020.71 (BEAST: 2020.87, error: 17.0 days).

Comparative outcomes organized across a four-part analytical taxonomy. Category I comprised unimodal concordance (19 cohorts, 45.2%), where active longitudinal sampling under stable substitution rates yielded direct convergence with BEAST credible intervals. Category II captured genealogical scope mismatches (9 cohorts, 21.4%). In these datasets, unpartitioned distance regression evaluated the crown of sampled sequences, whereas published studies conditioned on tree priors to date deep roots or introductions. Applying AutoClock normalized Laplacian spectral bisection ($K^*$) decoupled localized transmission crowns without taxonomic labels. Spectral deconvolution recovered the published 1960 mode in Dengue-3 within 1.6 years (1961.62 vs 1960.0) [29], matched the 2007 European introduction in African swine fever (2006.53 vs 2006.15), and isolated the acute 2005 island wave in Chikungunya La R{é}union (2005.10 vs 2004.80). Reconciling genealogical scope elevated benchmark concordance to 59.5% (25 of 42 cohorts), reaching $R = 0.86$ ($R^2 = 0.74$) across modern surveillance datasets. Category III captured regularization differences (8 cohorts, 19.0%). In datasets with narrow temporal depth or mutational sparsity, tree priors perform heavy shrinkage in Bayesian MCMC, manufacturing narrow intervals. Distance geometry computes exact finite-sample bounds via Fieller's theorem [30]. When temporal signal is indistinguishable from noise ($g \ge 1.0$), Fieller intervals expand to infinity, alerting researchers that data lack longitudinal signal. Category IV captured lineage heterotachy and rate mixtures (6 cohorts, 14.3%), where AutoClock separated asynchronous sub-epidemics.

# Discussion

The integration of autonomous artificial intelligence into empirical science represents a critical turning point. If autonomous agents continue to operate as disembodied conversationalists inside private local environments, computational science will fragment into an unobservable collection of irreproducible, post-verifiable claims. By providing artificial intelligence with an open, distributed computational body, our architecture establishes a new paradigm: verifiable agentic science governed by provenance by construction.

Scientific progress relies on the ability of independent researchers to inspect, challenge, and replicate computational findings. In conventional agent workflows, reproducibility depends entirely on post-hoc human discipline—an assumption that consistently fails in practice. Domain researchers interacting with conversational agents rarely record intermediate commands, pin operating system dependencies, or preserve raw data transformations.

Our architecture transfers the burden of reproducibility from human discipline to computational infrastructure. By executing analyses across Galaxy cyberinfrastructure, every analytical step is recorded upon an immutable directed acyclic graph. Tool versions, container digests, parameter values, and intermediate datasets are sealed in a permanent provenance ledger. This record is not an optional export—it is the physical mechanism through which compute occurs. Consequently, scientific claims generated through this framework carry complete execution lineage, ensuring that autonomous discoveries remain verifiable by the global scientific community.

The computational demands of frontier artificial intelligence threaten to centralize scientific discovery within well-funded commercial institutions. When automated research requires private compute clusters and proprietary cloud platforms, independent academic investigators are systematically excluded from high-throughput discovery.

We demonstrate that public, federally supported cyberinfrastructure can serve as the foundational execution surface for modern artificial intelligence. By pairing open foundation models and universal protocols with the Galaxy platform, we democratize autonomous science. A researcher at an under-resourced institution, equipped only with a standard laptop, can direct autonomous agents that orchestrate distributed supercomputing allocations, query petabyte-scale reference archives, and execute high-throughput pipelines across national high-performance clusters. Preserving the public scientific commons in the era of artificial intelligence is not merely an ethical priority—it is an infrastructural necessity for ensuring universal participation in scientific discovery.

Looking forward, coupling autonomous reasoning to open cyberinfrastructure establishes the foundation for a collaborative, planetary-scale scientific network. In this ecosystem, published workflows, curated reference databases, and execution engines communicate through standardized machine-readable protocols. Autonomous agents will not operate as isolated local assistants, but as distributed co-investigators capable of querying global workflow repositories, verifying analytical findings across independent compute clusters, and synthesizing collective biological knowledge. Grounding artificial intelligence in open, verifiable infrastructure ensures that the automated science of the coming decade remains transparent, reproducible, and universally accessible.

## Multi-Agent Analytical Divergence Benchmark
We evaluated analytical divergence across autonomous agents using an RNA-seq study of carbohydrate-mediated enterotoxin repression in *Bacillus cereus* (BioProject PRJEB86181, PMC12804731) [10]. The primary contrast compared two glucose-supplemented replicates (ERR14660412 and ERR14660413) against three baseline tryptic soy broth control replicates (ERR14660420, ERR14660421, and ERR14660422) from nineteen total libraries across five growth conditions.

To quantify planning variation, we evaluated 30 isolated agents across three foundation model families: ten Claude Opus 5.5 agents (Anthropic), ten Codex agents running GPT-6 Astra (OpenAI), and ten Gemini 3.8 Flash agents within Antigravity (`agy`, Google). Each agent received identical natural-language instructions in an empty local workspace directory with no prior session context, external memory, or access to Galaxy cyberinfrastructure (Table [tab:planning_prompt]). We parsed each generated plan across eight sequential analytical decisions: reference genome assembly, workflow engine, read trimming software, ribosomal RNA depletion strategy, read aligner, quantified genomic feature, differential expression model scope (19-sample pooled vs. 5-sample contrast-only), and log-fold-change shrinkage prior. Combinatorial trajectory diagrams were constructed from this discrete decision matrix. Model families exhibited distinct planning profiles. Claude plans aligned to *Bacillus pacificus* anQ-h4 and pooled variance across all nineteen libraries. Codex plans aligned to an alternative reference strain (*Bacillus cereus* ATCC 10987) and restricted the comparison to the five target replicates. Gemini plans showed severe instability across assemblies. They selected an unrelated strain in one plan and repeatedly reversed library strandedness. Aligning against a different bacterial strain alters gene coordinates and annotations. Inverting library strandedness discards or miscounts real transcripts. Pooling all nineteen libraries to estimate variance alters statistical power compared to analyzing only the five target replicates.

## Galaxy Model Context Protocol and Modular Skills
Agents interact with computational infrastructure through the Galaxy Model Context Protocol server (`galaxy-mcp`) [13]. The Model Context Protocol establishes an open standard for tool execution and data inspection. Rather than allowing agents to execute arbitrary local shell commands, the server provides forty-four structured endpoints. These endpoints enable agents to search tool registries, inspect dataset collections, launch workflows, and monitor execution states through standard input-output streams or remote HTTP connections. The server is implemented in Python utilizing the official BioBlend library to communicate with the Galaxy REST API. Transport mechanisms include standard input-output (stdio) for local CLI integration and streamable HTTP for web and remote clients. Authentication occurs through long-lived Galaxy API keys or OAuth2 token exchanges. The server provides structured error handling and schema validation across all parameter endpoints.

Domain expertise is provided through modular skill packages [14]. These skills teach language models standard bioinformatics conventions. Skills guide tool discovery, parameter selection, and collection manipulation idioms. For complex multi-step pipelines, Workflow Foundry skills compile validated workflow templates directly into agent memory [9]. By separating operational skills from the underlying compute runtime, the framework ensures that agents execute verified analytical procedures rather than generating unvalidated guesses.

## User-Defined Tool Architecture
User-Defined Tools are authored in YAML adhering to the `GalaxyUserTool` class definition. The tool wrapper specifies a mandatory container image hosted on public registries (Quay.io, Docker Hub), typed input parameters, declared output datasets, and an execution command. Commands are templated using sandboxed ECMAScript evaluation executed inside an isolated V8 runtime. Output files are claimed from the working directory through `from_work_dir` designations or dynamic dataset discovery patterns.

## Orbit Workbench and Execution Guard
Orbit is constructed as an Electron desktop application powered by a headless agent runtime built as an extension on Pi.dev. The runtime manages session context, system prompts, and tool registration. The execution guard intercepts tool calls via internal lifecycle hooks, classifying actions across model tiers, path security, and shell hazard. Local file writes are strictly confined to the workspace root using realpath resolution. Remote Galaxy jobs are tracked through YAML invocation blocks embedded within `notebook.md`, which are updated via background polling and asynchronous event handlers.

## Workflow Foundry Casting Pipeline
The Workflow Foundry compiler is implemented in TypeScript and Node.js. Molds are authored as Markdown documents carrying structured Zod-validated YAML frontmatter declaring pattern dependencies, manual references, and input-output schemas. The casting pipeline compiles Molds into target-specific agent skills. Synthesized workflows are validated statically using the `gxwf` validation engine, which verifies graph topology, step connectivity, and tool state against official Galaxy XML schemas and IWC exemplars.

### Table S1: Resource allocation, software environments, and compute footprints across three autonomous agent execution runs.
*All three runs re-analyzed the primary glucose versus control contrast from the Bacillus cereus transcriptomic benchmark (BioProject PRJEB86181) on an identical host machine (Ubuntu Linux workstation with 24 CPU cores, 62 GB RAM, and NVMe SSD storage). While all three platforms recovered the core biological signal of enterotoxin regulation, their resource management paradigms differed sharply. Gemini utilized a lightweight, greedy Unix shell pipeline with immediate file cleanup. Claude executed a heavy containerized Nextflow workflow that consumed over 100 GB of scratch disk and caused disk exhaustion until secondary quality control tools were disabled. Codex applied strict computational budgeting. It capped memory buffers and thread allocations per stream while maintaining an explicit ledger of purged intermediate files. None of the three runs produced persistent provenance records that external researchers could inspect or re-execute without rebuilding the local execution environment.*
